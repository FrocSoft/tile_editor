# Tile Editor

아이패드 미니에 맞춘 **오프라인 동작** 8비트 글리치 그래픽 편집기.
이미지를 8×8 픽셀 타일로 분절하고, 분절된 타일(또는 타일 블록)을 브러시로
BG/스프라이트 두 레이어에 찍으며 글리치 아트를 만든다.

서버 없이 정적 파일만으로 동작하는 PWA — 모든 작업물은 기기(IndexedDB)에 저장된다.

## 아이패드에 설치하기 (오프라인 사용)

1. 리포 설정에서 **GitHub Pages**를 켠다: Settings → Pages → Source를 **GitHub Actions**로 선택.
   main 브랜치에 푸시하면 `.github/workflows/pages.yml`이 자동 배포한다.
2. 아이패드 사파리에서 배포된 주소(`https://<계정>.github.io/tile_editor/`)를 연다.
3. 공유 버튼 → **"홈 화면에 추가"**.
4. 이후에는 와이파이 없이도 홈 화면 아이콘으로 실행 가능 — Service Worker가
   앱과 에셋 전체를 기기에 캐싱해 둔다.

## 사용법

- **🗂 에셋**: `assets/` 폴더의 스프라이트를 폴더별로 탐색해 선택하면 8×8로 분절된다.
  사진/파일에서 직접 가져오기도 가능.
- **소스 패널**(하단): 탭 = 타일 하나 선택, **드래그 = 사각 범위 선택** → 타일 블록 브러시.
  "캔버스에 배치"로 소스 전체를 활성 레이어에 깔 수 있다.
- **레이어**: `BG`/`SPR` 세그먼트로 활성 레이어 전환, 👁 버튼으로 레이어별 표시 토글.
  스프라이트 레이어가 배경 위에 합성된다.
- **캔버스 크기**: 상단 `W±`/`H±` 버튼으로 1타일 단위 조절.
- **실물 캔버스 맞춤**: 프로젝트 서랍에 실물 치수(㎜)를 입력하면 비율에 맞는
  타일 수 조합을 해상도별로 추천 — 탭 한 번으로 캔버스 크기 적용.
- **도구**: 🖌 스탬프 · ▦ 패턴 채우기(브러시 블록으로 드래그 영역 타일링) ·
  ⬚ 선택(드래그 이동/복제/삭제/브러시화) · 👆 타일 집기(탭한 칸의 타일을 브러시로) ·
  ◽️ 지우개 · ⇆ 행/열 밀기(글리치) · 🎲 랜덤 교란
- **브러시 변환**: 브러시 미리보기 옆 ⟳(90° 회전) ⇋(좌우 반전) ⇅(상하 반전)
- **🎨 NES 팔레트**: 실제 NES PPU 방식 — 마스터 팔레트(기본 NES 54색, `.pal`/`.hex`/`.gpl`
  파일로 교체 가능)에서 색을 골라 서브팔레트(3색+공용 배경색) 4개를 구성.
  "적용"은 선택 영역(없으면 전체)의 타일을 서브팔레트 4색으로 양자화(타일당 4색 제한 재현),
  "색 대치"는 캔버스를 탭해 집은 원본 색을 마스터 팔레트의 원하는 색으로 교체.
  배경색 옆 **"채우기"**를 켜면 실제 NES처럼 배경색이 모든 레이어 아래에 깔려
  여백과 타일 속 빈 픽셀까지 그 색이 된다(내보내기에도 반영) — 끄면 투명하게 나간다
- **제스처**: 한 손가락/애플펜슬 = 도구, 두 손가락 = 핀치 줌·팬
- **⬇︎**: PNG(원본 1×) 또는 Aseprite 내보내기 — 파일명은 프로젝트 이름.
  새 캔버스 기본 이름은 `SCR-XXDD`(앞 두 자리 랜덤, 뒤 두 자리는 만든 날짜의
  day-of-year 36진수 코드)

## 클라우드 (비공개 리포에 저장)

작업물과 에셋을 **본인 소유의 비공개 리포**에 두면 기기 사이에서 이어서 작업할 수 있고,
사파리 데이터가 지워져도 남는다. 앱 코드는 공개 리포(Pages)에서 배포되지만
데이터는 이 비공개 리포에 들어가며, 토큰은 기기의 IndexedDB에만 저장되고
백업 파일에도 포함되지 않는다.

준비:

1. 비공개 리포를 하나 만든다 (예: `tile_editor_data`).
2. GitHub Settings → Developer settings → Personal access tokens → **Fine-grained**에서
   그 리포에만 **Contents: Read and write** 권한을 준 토큰을 만든다.
3. 앱의 프로젝트 서랍 → "클라우드"에 계정·리포·토큰을 넣고 **연결**.

동작:

- **작업물**: 저장할 때 자동으로 `projects/<이름>.json`으로 올라간다(체크박스로 끌 수 있음).
  받는 건 항상 수동 — 저장된 작업 목록에 클라우드에만 있는 항목이 ☁︎로 뜨고 "받기"를 누르면
  내려받아 열린다. 다른 기기가 먼저 고쳤으면 덮어쓰기 전에 물어본다.
- **에셋**: 에셋 서랍에서 폴더 이름을 적고 이미지를 고르면 `assets/<폴더>/`에 바로 올라가고
  목록에 즉시 나타난다(배포를 기다릴 필요 없음). 한 번 받은 에셋은 기기에 캐시되어
  오프라인에서도 쓸 수 있다.

## 저장 위치와 백업

- 작업물은 전부 기기 안 웹앱 전용 저장소(IndexedDB)에 저장되며 서버로 전송되지 않는다.
- 설정 → Safari → "방문 기록 및 웹 사이트 데이터 지우기"를 실행하면 작업물도 삭제되므로,
  프로젝트 서랍의 **"전체 백업 내보내기"**로 저장 작업·현재 캔버스·팔레트를 한
  `.json` 파일로 만들어 파일 앱/iCloud에 보관해 둘 것. **"백업 가져오기"**로 복원되며,
  기존 저장 작업을 지우지 않고 백업분을 추가한다.

## 에셋 추가하기

에셋은 리포의 `assets/` 아래 폴더별로 둔다:

```
assets/
  <폴더명>/
    sprite1.png
    sprite2.png
```

### 아이패드에서 (권장)

사파리에서 github.com의 리포 → `assets/<폴더>` → **Add file → Upload files** →
PNG를 여러 장 골라 **Commit changes**. GitHub Actions가 `index.json`을 다시 만들고
배포하므로(1분쯤) 앱을 열면 🗂 목록에 나타나고, 이후에는 오프라인에서도 쓸 수 있다.
새 폴더는 업로드 화면 위쪽 경로칸에 폴더 이름을 입력하면 만들어진다.
여러 장을 한 커밋에 올리면 Pages 빌드가 한 번만 돌아 시간당 빌드 제한을 피할 수 있다.

타일 PNG는 색 수가 적어 장당 수십 KB 수준이라(현재 21개 합쳐 277 KB)
Pages 사이트 1 GB 한도에는 사실상 걸리지 않는다.

### 데스크탑에서

PNG를 넣은 뒤 인덱스를 갱신하고 커밋한다 (Actions 배포 시에도 자동 재생성된다):

```sh
python3 tools/build_asset_index.py
```

샘플 에셋과 앱 아이콘은 `python3 tools/generate_samples.py`로 다시 만들 수 있다.

## 로컬 실행

```sh
python3 -m http.server 8000
# http://localhost:8000
```

Service Worker는 HTTPS 또는 localhost에서만 동작한다.
